# Architecture

```text
Tauri WebView / browser development UI ─┐
MCP stdio bridge ───────────────────────┼─ Unix socket (local user only)
Native UNGE renderer ───────────────────┘          │
                                     Rust service / single workspace owner
                                               │
                            revision-checked command → validate → atomic save
                                               │
                             Document / history / reports / candidates
```

`design-core` is independent of Tauri, React and GPU libraries. It holds typed combinational circuits and the behavioral evaluator. `studio-service` owns the single mutable Workspace behind a mutex, an OS file lock, and a private Unix socket. Long workspace paths use a deterministic socket directory under the user’s temporary directory to fit macOS socket-path limits. It validates a clone and only publishes it after the disk write succeeds. `.logic/workspace.json` contains schema version, document, undo/redo stacks, revisions, reports, experiments and shared panel/language preferences. Durability uses an fsynced move journal and atomic checkpoints with directory sync; this is not an SQLite database.

WebViews keep read snapshots and transient interaction drafts, never an independently editable design. Every persistent edit reaches the Rust command service. The explicit expected revision is never silently rebased. WebViews check `project.sync` every 800 ms and on Tauri change notifications. A service-session cursor plus a mutation sequence detects changes beyond circuit revisions (selection, locale, panels and verification results). Unchanged replies contain only cursor/changed. `scope:web` returns a base cursor and an ordered list of committed deltas. The journal retains at most 64 entries / 8 MiB serialized deltas; initial requests, expired/unknown cursors, future cursors and service restarts get a full snapshot. Deltas contain changed root fields, node/edge upserts/removals, history/experiment entity updates and explicit order only when natural append/removal order is insufficient. Diagnostics are recalculated only for semantic graph/name changes, not position-only moves. TypeScript validates the base and entity order, applies all deltas without mutating the old snapshot and advances its cursor only after successful application. On an invalid base it retries a full sync. Concurrent notifications schedule a follow-up refresh instead of being dropped. View mutations use `view.command` acknowledgments, keeping full circuit snapshots out of mutation replies; ordinary core/MCP tool response contracts remain unchanged. Successful persisted mutations advance the sequence; rejected patches and failed disk writes do not. Service restarts create a new session cursor and force a fresh document.

Native polling runs on a worker with a 100 ms fallback and a bounded wake channel after GUI commits. `scope:native_delta` uses the same bounded journal, filtered to revision, selection, locale, panels and document entities. A typed transactional applier checks base cursors, removals and entity order. Metadata-only changes retain the original Arc<Document>; node/edge changes clone the cached typed document and replace only affected entities. Missing/expired bases, service restarts or application errors trigger a full native snapshot. History, experiments and reports never enter this stream. Rendering reads the cache and never performs socket snapshot reads on the event loop. Frame stamps suppress unchanged frames; reparenting layouts are retried. Gesture projections and hit-test indexes are cached across pointer moves and apply derived node/edge commands. Canonical and typed-cache documents share 32-entity blocks and ID indexes. Coordinate updates copy affected blocks; comparisons skip shared blocks. Structural changes retain full identity/order reconstruction. Live service/IPC/WebView/native timing probes and their limits are documented in NATIVE-PERFORMANCE.md.

`studio-renderer` derives a retained UNGE rendering projection from the validated canonical document. Domain-separated SHA-256 render IDs preserve identity across reordering, imports and Undo. A derived UNGE Editor (zero history) applies move/add/remove/connect/disconnect batches; port changes recreate only affected nodes and their connections. SceneChanges feeds SceneIndex’s bounded BVH update/refit path, with full rebuild when edit/overlay limits are exceeded. Name-only changes update the label catalog without geometry/index rebuilding. This cache never accepts independent user mutations; canonical revisions still own conflict checks and persistence.

SceneIndex retains per-node Quad/text fragments and tessellated cable geometry. Keys cover preview position, selection, exact zoom, locale, theme and label metadata. Committed node updates invalidate that node and incident edges; panning reuses world-space fragments. Label paint offsets are rebased during scene assembly so stacking remains identical to a fresh scene. Camera/zoom, visibility assembly and the final render pass still cover the visible scene; this is retained geometry and differential uploads, not dirty-rectangle framebuffer rendering. GPU Quad and glyph buffers compare instance-aligned ranges, merge small gaps and fall back to one write above 64 ranges; buffer reallocations force a full upload. SceneIndex, fragment caches, glyph atlas and GPU buffers remain in Rust. See PERFORMANCE.md for measured limits.

The native view currently fits the document and follows selection/locale. WebView editing uses the same port-anchor formula, role palette and node dimensions, with an extra simple cable detour around intervening cards. This detour is not a general-purpose EDA router. Native navigation/input and child WebView composition are integrated in the main editor.

MCP runs as a separate stdio process and forwards structured commands to the same socket. Default read-only mode blocks editing, verification jobs, and synthesis. `--allow-write` authorizes these tools; adopting an experimental candidate is intentionally absent from MCP tool discovery and exposed only to GUI commands. This is a local-user trust boundary, not multi-user access control: processes with access to the owner's socket can use the command service.

Yosys uses generated HDL and a fixed script in an isolated run directory, without a shell. The process is limited to 30 seconds, and each run stores its revision, source, log, netlist and result. It does not load arbitrary user scripts, but is not an OS sandbox. Only one in-process workspace owner can save the file; separate result directories prevent artifact collisions.

Input limits: 2,000 nodes, 8,000 edges, 512 patch operations, 1 MiB IPC/MCP request, 4,096 verification vectors, 8 candidates/experiment, 20 experiments, 100 undo snapshots. These are hard caps, not performance guarantees. History is currently snapshot-based. Results stay associated with their originating revision.

## Native editing integration

The desktop main window now owns a native UNGE Surface with an opaque child WebView for controls. `src-tauri/src/native.rs` receives Tao pointer events, bounds them to the graph region, and forwards them to the Rust `EditorView`. UNGE returns gesture commands; the adapter converts these into canonical design-core operations. Moves stay preview-only until release, and edits commit with the observed revision. Selection, camera and gesture previews remain in Rust. Rendering uses the same viewport and preview as hit testing. The browser-only SVG path is retained.

macOS live checks on 2026-11-09 covered node drag (r0→r1), GPU selection following into the inspector, disconnect/reconnect (r2→r3), inspector floating and return to the controls panel. Controls occupy independent child WebViews across left/right/bottom regions. Cross-monitor DPI testing remains future work.

## Native panel regions

Each panel has its own child WebView. Rust computes left/right strips and a bottom strip from shared preferences, distributing multiple panels within a strip. The native graph hit region uses the same rectangle. The toolbar remains a separate child WebView. Floating reparents the existing panel WebView into a native window; docking reparents it into the workspace. Close hides the panel and preserves its WebView/drafts. Toolbar buttons restore the most recent dock location during the session. OS close on floating windows is intercepted and uses the same hide path. Shared panel modes and remembered dock destinations for hidden/floating panels survive restart.

Live macOS QA covered all three panels in all three dock destinations, floating and returning, header close/reopen, and floating-window OS close/reopen. Windows/Linux and physical multi-monitor DPI transitions remain unverified. Native docking supports menus and captured header drags; splitter dimensions are adjustable and persisted.

## Layout gestures

Header and splitter WebViews forward captured pointer screen coordinates over a serialized command queue. Rust owns the active gesture, original dimensions, target detection, cancellation and geometry clamps. Docking uses the existing same-WebView reparenting path on release. A translucent GPU rectangle marks the active target in the graph. Splitters modify Rust-owned logical dimensions; layout converts them to physical bounds and shares the resulting graph hit rectangle with native input. Rust atomically saves dimensions, dock restore destinations and floating geometry to `.logic/panel-layout.json`; placement modes remain in the canonical workspace preferences. Startup restores hidden/floating panels, clamps floating frames to available screens and retains logical dimensions across restarts. Floating windows have a hidden anchor child so macOS Wry measures the actual window instead of the reparented panel bounds. A placement mutex serializes reparenting; main-thread layout uses try_lock to avoid blocking on Wry’s window-id lock while a worker waits for reparent completion.


## Optional live timing probes

`LAS_UI_TRACE=/absolute/path.json` enables bounded (256-sample) native-move timing records; normal execution does not record them. Timing starts just before handling the final native pointer event that produces a move patch. Rust records successful commit response and native draw/present-call return. React acknowledges its committed revision after two requestAnimationFrame callbacks; the receiving Rust process timestamps acknowledgments using the same Instant origin. This measures paint opportunities, not physical scan-out or GPU completion. `LAS_WEB_SYNC_FULL=1` forces full snapshots only for comparison of the same client/build. Isolated seeded workspaces keep performance fixtures out of the user’s design.


## Durable move commits

Coordinate-only patches retain revision checks, atomic batch semantics, node lookup and finite/bounded coordinate checks, while reusing the validated graph topology. Semantic edits/imports keep full graph validation. Current, Undo/Redo and candidate document snapshots are shared Arc<Document> values; transactional Workspace clones copy document references and edits allocate their new document once. Metadata containers still clone. Undo/Redo swap references, with a recomputable per-entry JSON byte cache enforcing the combined 100-entry / 16 MiB limit. Compact GUI dispatch avoids constructing full snapshot responses; ordinary core/MCP contracts are unchanged.

`.logic/workspace.json` is a compact streamed checkpoint, not necessarily the latest state. `.logic/workspace.wal` holds length-prefixed, SHA-256 checked, sequenced position patches and actors. Both files are needed for a filesystem backup; use the service/export commands for current IR. Moves append and fsync before publication/acknowledgment. After 128 move records or 4 MiB, the next mutation checkpoints; other persisted mutations checkpoint immediately. Checkpoints stream through a 1 MiB BufWriter, explicitly check flush, fsync their file, rename atomically and fsync the directory before best-effort WAL pruning. A checkpoint sequence skips records already covered if interruption occurs before pruning. Startup replays later records through the canonical revision/Undo path. A partial final frame is truncated; complete checksum/schema/sequence errors preserve the journal and fail open. Failed ordinary writes do not publish state/cursors. An uncertain rollback or post-rename directory-sync failure blocks further writes until restart. This is process-crash recovery with explicit fsync boundaries, not hardware power-loss certification.

Shared snapshot and checkpoint before/after measurements, including 140 real 2,000-node moves and one compaction, are recorded in [HISTORY-PERFORMANCE.md](HISTORY-PERFORMANCE.md). The JSON schema remains unchanged.


## Sparse position updates

Document arrays are JSON-compatible `Entities<T>` values with shared 32-record blocks, a shared ID index and per-block encoded-size caches. Current/history/candidate Arc documents share these blocks. Indexed coordinate mutations invalidate only the changed block and its byte count. Service and retained-projection comparisons inspect records only in changed blocks; native upserts update known IDs directly. Node/render-ID maps are shared. Structure/identity changes use the existing general comparison, validation and resynchronization paths. After a native commit, a revision/epoch gate avoids drawing stale canonical state before the worker delivers the acknowledged revision. No frame images cross IPC. [SPARSE-MOVE-PERFORMANCE.md](SPARSE-MOVE-PERFORMANCE.md) records normal-path latency and remaining full-work boundaries.


## Startup recovery

Layout validation precedes service startup so damaged panel preferences can be repaired without starting a competing owner. A service-open or layout error launches a dedicated recovery WebView instead of failing application setup. Its React entry loads independently of the normal store/polling lifecycle. Recovery commands accept no client-supplied root and require the recovery window; Rust holds the root and failure category.

Successful checkpoint saves retain the prior checkpoint inode as `workspace.previous.json` through a temporary hard link and rename. Filesystems without hard-link support use a synced copy before replacement. The final directory sync covers checkpoint/previous renames before journal pruning. This is one prior checkpoint, not an unlimited backup/version service.

Offline recovery acquires the existing owner lock, validates candidate documents and history, and checks a content token. Every existing checkpoint, previous checkpoint, journal, layout and incomplete checkpoint temporary file is copied and fsynced into a private recovery directory with a manifest before active replacements. A second content check catches changes during backup. Circuit recovery atomically installs the selected checkpoint then an empty journal; layout recovery replaces only layout preferences. The original bytes remain in the archive. An interrupted recovery can require another recovery attempt; original archives are retained. Recovery reopening launches the exact current binary with an absolute `--workspace` argument and detached stdio, avoiding macOS bundle-identifier ambiguity and environment-variable loss.

See [RECOVERY.md](RECOVERY.md) for boundaries and actual macOS verification.


## Workspace selection

Rust owns the active root and application-level selection store, independently of WebViews. macOS uses an asynchronous native folder sheet parented to the invoking window. Only controls/recovery/workspace-start WebViews can invoke selection; a process-level guard prevents overlapping sheets. Cancel and the current canonical directory are no-ops. Chosen paths are validated/canonicalized, saved through unique temporary files with file/directory fsync, and opened with the exact executable and explicit root argument. Failed process launch rolls back the stored selection. Circuit files are not imported or overwritten during selection.

Startup precedence is explicit `--workspace`, `LAS_WORKSPACE`, remembered UI selection, then existing development/release defaults. An invalid selection file or unavailable remembered folder opens a separate starter WebView and never creates data at that missing path. A valid empty folder initializes through the normal Rust service on open. `LAS_SETTINGS_ROOT` isolates application-selection preferences during tests. The toolbar opener is memoized, fetching its current root once rather than on each circuit revision. Starter and recovery entries do not load the normal store/polling lifecycle. See [WORKSPACES.md](WORKSPACES.md).

`verify.rtl` captures an Arc document and expected revision, then releases the Workspace lock before running the selected Icarus or Verilator backend. A separate per-service try-lock prevents overlapping RTL jobs. Only validated generated RTL and a generated testbench reach the tools; no client scripts or shell arguments are accepted. Results and reproduction files live in revision-tagged run directories, without modifying the circuit or behavioral report. See [RTL-VERIFICATION.md](RTL-VERIFICATION.md).
